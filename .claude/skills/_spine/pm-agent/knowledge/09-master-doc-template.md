# 09 — Master Doc Template

> At project close, PM Agent generates a comprehensive technical reference any future developer can read to understand the entire project. This is the developer onboarding doc for the codebase.

---

## Why this exists

When a future developer (your team member or a new hire) needs to work on this project — to add features, fix bugs during warranty, or hand off to client's in-house team — they need ONE document that explains everything.

Without this, they spend days reverse-engineering, asking the original devs (who may have moved on), or guessing from the code.

This doc is the "you walked into a new codebase, read this first" file.

---

## When generated

At project close, AFTER:
- Project verification report PASS
- G6 (pre-launch) confirmed
- Project is in `delivered` status

Generated by PM Agent. Saved to:
- `/projects/[client]/final-deliverables/master-doc.md` (final version)
- Also copied into the repo: `/[repo]/AGENCY-MASTER-DOC.md`

## Generation rules

PM Agent generates the master doc by:

1. Reading project.json (gets project identity, team, dates, milestones, budget, bugs, audit log)
2. Reading spec.md (gets scope, deliverables, constraints)
3. Reading design-tokens.json + section-map.json (gets design + structure)
4. Reading the repo structure (gets file layout)
5. Reading adherence reports + QA reports (gets quality evidence)
6. Reading audit log (gets decisions made)

Output is a complete `master-doc.md`. Formatting is consistent across projects so future devs always know where to look.

---

## Quality bar

A good master doc:
- A new dev can read it in 20-30 minutes and understand the project
- Explains WHY decisions were made (not just what)
- Documents what's editable vs. requires-dev
- Lists known limitations honestly
- Includes maintenance guidance

A bad master doc:
- Just re-states the spec
- Misses architectural rationale
- Doesn't document custom logic locations
- Hides known limitations
- Doesn't help future maintenance

PM Agent should ask itself: "If a junior dev who has never seen this project reads this, can they make a sensible change tomorrow?" If no, revise.
