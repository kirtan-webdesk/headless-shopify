# 08 — Update Document Templates

> The 7 client-facing update documents PM Agent generates throughout a project. Style will be tuned to your inspiration documents (pending from you).

---

## The 7 update types

| # | Update | When generated | Audience | Purpose |
|---|--------|----------------|----------|---------|
| 1 | Sprint update | End of each sprint | Internal team + Internal PM | Status, what shipped, what's next |
| 2 | Milestone update | End of each milestone | Client (via Internal PM) | Major delivery summary, payment trigger |
| 3 | Data migration update | At key migration checkpoints | Client + dev team | Data parity status, transformation notes |
| 4 | Desktop preview update | When desktop UX is reviewable | Client | Invite to review desktop experience |
| 5 | Responsive preview update | When mobile/tablet is reviewable | Client | Invite to review responsive |
| 6 | SEO update | At SEO milestones | Client + SEO team | Schema, redirects, baseline status |
| 7 | Go-live update | Pre-launch and post-launch | Client | Launch readiness + cutover plan |

---

## General format rules

All update documents share these conventions:

- **Top:** project name, project ID, date, version (in case of revisions)
- **Status line:** ON_TRACK / FLAGS / DELAYED / READY
- **Distribution list:** who receives this update
- **Brevity:** PM Agent should produce a one-page-equivalent update unless project complexity requires more
- **Action items:** if any actions required from client, list them with deadlines
- **Next update date:** when the next update of this type is expected

Style will follow your inspiration documents (PENDING from you). Until those arrive, PM Agent uses these neutral templates.

## 1. Sprint Update

### When
End of each sprint, after sprint adherence verification passes.

### Audience
Internal: PM, Tech Lead, QA Lead, Designer (if relevant), Frontend/Backend Dev.

### Template

```markdown
# Sprint Update — S[sprint-id]: [Sprint Name]

**Project:** [Project Name] ([Project ID])
**Sprint:** S[sprint-id]
**Milestone:** M[milestone-id]
**Date:** [YYYY-MM-DD]
**Status:** PASS | PASS_WITH_FLAGS | FAIL

---

## What Shipped This Sprint
- [Output 1, with link to PR or section file]
- [Output 2, with link]
- [Output 3, with link]

## Acceptance Criteria Outcome
- [✓] AC1: [criterion] — VERIFIED
- [✓] AC2: [criterion] — VERIFIED
- [⚠] AC3: [criterion] — PARTIAL ([explanation])

## QA Module Results
- Module 1 (Theme/Code validity): PASS
- Module 2 (Functional): PASS
- Module 3 (Responsive): PASS
- Module 4 (Cross-browser): PASS
- Module 5 (Accessibility): PASS — 0 axe violations
- Module 6 (Performance): PASS — Lighthouse 84 (target ≥80)
- Module 7 (SEO): PASS
- Module 8 (Security): PASS

## Estimation
- Estimated: [N] hours
- Actual: [N] hours
- Variance: [+/-X%]

## Bugs Found
- P1: 0
- P2: 0
- P3: 1 (deferred to next sprint per CR)
- P4: 2 (documented as known limitations)

## Risks Update
- No new risks
- R1 (content delay): mitigated; content delivered on time

## Drift Check
- Out-of-scope additions: NONE
- Spec changes during sprint: NONE

## Next Sprint
- S[next-sprint-id]: [Sprint Name]
- Expected start: [date]
- Expected end: [date]

## Preview
- Dev theme: [preview URL with preview_theme_id token]

---

Distribution: PM, Tech Lead, QA Lead, Frontend Dev, Backend Dev (if relevant), Designer (if relevant)
Generated by: PM Agent v1.0
Next sprint update: end of S[next-sprint-id]
```

---

## What's Configured

### Technical SEO
- ✓ XML sitemap generated and submitted to Google Search Console + Bing Webmaster
- ✓ robots.txt configured
- ✓ llms.txt generated (for AI crawler instructions)
- ✓ Canonical URLs implemented on [N] pages
- ✓ No accidental noindex tags
- ✓ HTTPS across all pages
- ✓ Mobile-responsive (PageSpeed mobile-friendly test: PASS)

### On-Page SEO
- ✓ Title tags: [N] pages with unique titles (50-60 char target)
- ✓ Meta descriptions: [N] pages (150-160 char target)
- ✓ Heading hierarchy: [N] pages audited, all single H1, no skipped levels
- ✓ Image alt text: [N] images with alt, [N] decorative with empty alt
- ✓ Internal linking audit complete

- ✓ Website schema

- ✓ Product schema ([N] products)

## 7. Go-Live Update

### When
Two versions of this update:
- **Pre-launch:** 2-7 days before launch, summarizing readiness
- **Post-launch:** within 24 hours of launch, confirming success + monitoring status

### Audience
Client + entire internal team.

### Pre-launch template

```markdown
# Go-Live Update — Pre-Launch Readiness

**Project:** [Project Name]
**Launch target:** [YYYY-MM-DD HH:MM Timezone]
**Status:** READY | FLAGS | NOT_READY

---

## Pre-Launch Checklist Status

[Status summary from Delivery Head's dynamic pre-launch checklist]

- ✓ All deliverables present (project verification: PASS)
- ✓ All P1/P2 bugs resolved
- ✓ All integrations configured + tested
- ✓ Lighthouse performance ≥ target on all key pages
- ✓ Accessibility: axe-core 0 violations
- ✓ SEO baseline complete + schema validated
- ✓ Redirects mapped + verified (if applicable)
- ✓ Analytics configured + test events received
- ✓ Backup of current live theme created
- ✓ Rollback plan documented
- ✓ Client sign-off received

[List any flags or notes]

## Launch Plan

### Cutover sequence
1. [Step 1 — e.g., publish theme via Shopify MCP]
2. [Step 2 — e.g., update DNS if applicable]
3. [Step 3 — e.g., trigger analytics tracking verification]
4. [Step 4 — e.g., smoke test live URL]

### Personnel during launch
- Launch lead: [name]
- On-call dev: [name]
- On-call QA: [name]

### Rollback trigger conditions
- Site down for > 5 minutes
- Checkout broken (no transactions complete)
- Critical SEO issue (noindex or major content loss)
- Other [defined per project]

## What Happens Immediately After Launch

- 24-hour synthetic monitoring active
- Team monitoring analytics for unusual patterns
- Bug triage on-call
- Post-launch update will be sent within 24 hours

## Action Required from You

- [Final sign-off if not yet given]
- [Notify your team of launch time]
- [Pause any marketing campaigns during cutover window if applicable]

---

Generated by: [Internal PM + Delivery Head]
```
