## New tools

### `tools/scripts/filter-inventory-for-edition.py`

Filter canonical `decision-inventory.md` down to a single edition's D-codes.

```bash
python3 tools/scripts/filter-inventory-for-edition.py \
  skills/_decisions/decision-inventory.md \
  /tmp/shopify-inventory.md \
  --edition shopify
```

Runs at packaging time. Output is dropped into the edition bundle in place of the canonical inventory.

### `tools/scripts/verify-edition-integrity.sh`

Test script that verifies an extracted edition bundle has no cross-platform contamination.

```bash
tools/scripts/verify-edition-integrity.sh /path/to/extracted/shopify shopify
tools/scripts/verify-edition-integrity.sh /path/to/extracted/wordpress wordpress
tools/scripts/verify-edition-integrity.sh /path/to/extracted/full full
```

Exit code 0 = clean. Exit code 1 = contamination detected. Runs in CI before shipping any bundle.

Rules per edition:
- **Shopify:** must have `skills/shopify/`, 5 project types present; must NOT have `wordpress-woocommerce/`, `bigcommerce/`, `magento-adobe-commerce/`, `wp-safe-deploy.sh`, or D-WP codes in inventory. Must have ≥ 4 Shopify D-codes.
- **WordPress:** must have `skills/wordpress-woocommerce/`; must NOT have other platform arms or Shopify project D-codes. Must have ≥ 4 D-WP codes.
- **Full:** must have all 4 platform arms + inventory with codes from both Shopify AND WP.
- **All editions:** validator present, persona present, forbidden-global present, README with ≥ 5 lines (catches the stub regression).
