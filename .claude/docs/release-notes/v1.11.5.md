## Root cause 1 — Cascade tag derivation gap

**Symptom:** Files 20 (Elementor architecture), 22 (QA checklist), 24 (WC CSS conflicts) were tier-1 with load_when arrays like `["woocommerce-platform-active", "elementor-build", "theme-build"]`, but the orchestrator's active-tags set for a WC+Elementor project only contained `wordpress-platform-active`. Result: file 24 never loaded on WC projects. File 22 never loaded at G4/G5/G6 without explicit `qa-active` tag. File 20 loaded but its selector-discipline warnings weren't reinforced by 22's pre-reorder audit.

**Fix (D-CASCADE-01):**

`_spine/orchestrator/knowledge/06-agent-cascade.md` — expanded "Active task tags" list to include:
- WC platform tags: `woocommerce-platform-active`, `platform-woocommerce`
- Canonical platform tags (v1.11.5+): `platform-wordpress`, `platform-shopify`, etc.
- Builder tags: `elementor-build`, `acf-classic-build`, `block-editor-build`, `sage-build`, `wordpress-page-builder-build`
- Activity tags: `theme-build`, `code-production`, `performance-task`
- Full gate range: `g0.5-stage` through `g6-stage`
- All agent tags: `agent-pm`, `agent-designer`, `agent-qa`, etc.

Plus a new section: **"Task tag activation rules (v1.11.5+) — CRITICAL"**. Documents how the orchestrator MUST derive the tag set from `CLAUDE.md.platform_config` at session start. Includes explicit derivation rules and a worked example for WC+Elementor.

**Bonus fix:** `wordpress-woocommerce/knowledge/11-woocommerce-architecture.md` bumped tier 2 → tier 1 with load_when including WC tags. Was previously on-demand only (D-WP-TIER-01).

## Root cause 2 — QA CRITICAL was documented but not enforced

**Symptom:** File 22 verdict rules said "FAIL: Any CRITICAL OR > 3 MAJOR" — proper blocking language. But `_spine/qa-agent/SKILL.md` didn't explicitly say "FAIL = gate does not advance." Prior behavior treated CRITICAL findings as flag-and-continue advisories.

**Fix (D-QA-GATE-BLOCK):**

`_spine/qa-agent/SKILL.md` — new section **"Gate blocking policy (v1.11.5+)"**. Key language:

> FAIL is not advisory. FAIL is enforcement. The orchestrator MUST NOT emit a G4 / G5 / G6 sign-off while any CRITICAL is open. Human sign-off is impossible on a FAIL verdict — the human is asked to fix or explicitly override with a documented exception filed to `_decisions/`.

Plus rejection of "soft advisory" behavior:
- QA finds CRITICAL → bug written with severity CRITICAL
- Sprint/milestone/gate verdict → FAIL
- FAIL reported to orchestrator + PM Agent
- QA does NOT continue advancing pipeline
- Waits for fix + retest OR human override with `_decisions/` exception

Includes explicit mapping of the DSM failure modes reported on 2026-07-02:
- WC-CSS-CONFLICT-01 → custom cards fighting WC CSS
- ELEMENTOR-SELECTOR-01 → section reorders using generated element IDs
- ELEMENTOR-CSS-REGEN-01 → programmatic injects missing regeneration

Also expanded QA Agent's "You DO NOT" list:
- Downgrade CRITICAL findings to advisory
- Advance a gate with any CRITICAL open
