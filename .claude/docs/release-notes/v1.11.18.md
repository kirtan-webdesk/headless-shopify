## The scaffold-tag bug (my authorship)

My v1.11.8 headless scaffold shipped `09-forbidden.md` with `load_when: ["headless-code-production", "code-review"]`. Both tags were registered nowhere:

- `headless-code-production` — the universal `code-production` covers this pattern; my scaffold's arm-prefixed version was speculative and never registered
- `code-review` — spec says `agent-code-review`; my scaffold used the short form

An unknown `load_when` tag doesn't error. The file simply never loads. For `09-forbidden.md`, that means gate blockers never enter context. For eight months my scaffolded headless forbidden file has been shipping with load conditions that no loader knows about.

The Headless window caught it during their content authoring, corrected their own file (uses `code-production` + `agent-code-review`), and flagged the underlying spine gap that made this class of bug silent. The validator's new WARN check exists specifically to make this class of bug loud rather than invisible.

## Also caught: ship-bundle.sh silent-exit bug

Also mine (v1.11.16). The new previous-manifest lookup used `ls -1 $DEST_DIR/$SLUG_PATTERN` under `set -euo pipefail` — when the glob doesn't match anything (clean directory, no previous zip), `ls` fails, `pipefail` propagates, `set -e` exits the script with no error message. Shopify and full initially failed with silent aborts on this bug. Fixed with `|| true` on the pipeline. Same class of bug the Shopify window flagged in v1.11.16 (silent SKIP on missing manifest) — I patched the SKIP path but not the pipeline itself. Full fix now in place.
