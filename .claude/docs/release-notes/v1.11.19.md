### Item 3 — Validator arm-scoped glob bug fixed

The Headless window's reproduction was exact. `gather_arm_registered_tags(root)` globbed `skills/*/knowledge/00-overview.md` relative to `root`. When run from repo root, worked. When run from `skills/headless/` — the natural thing for an arm window to do — resolved to `skills/headless/skills/*/knowledge/00-overview.md` which matches nothing. Zero arm-registered tags gathered, so every correctly-registered tag WARNed.

**Fix:** new `find_repo_root()` walks up from the passed root looking for a `skills/` directory. Globs against that, not against the passed root. Verified both scopes now gather the same 30-tag set including `audit-active`:

```
root=.       count=30, audit-active present=True
root=skills/headless   count=30, audit-active present=True
```

Arm-scoped Headless run now reports **0 errors, 0 warnings** on 7 files — matches the arm's actual state.

**Why this was almost worse than "just noise":** the release notes said WARN would promote to FAIL after all arms audit their tags. On that day, this bug would have false-FAILed every arm-scoped run — blocking the audit workflow it exists to enable. Also would have inflated arms' per-arm triage counts, pushing them to "fix" tags that were never broken and away from the arm-registration mechanism §6 was just amended to bless. Caught before promotion.

**Also added to universal set:** `audit-active` (visible in the machine-readable tag registration table the Headless window added to 00-overview §7).
