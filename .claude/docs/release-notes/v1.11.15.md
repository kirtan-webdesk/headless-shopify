## The `scan_arm_version_bump()` rewrite (Shopify window's technical correction)

**Their critique, verbatim from HANDOFF:**

> `scan_arm_version_bump()` fired on my build as a false positive — I had bumped both versions correctly, but it compares mtimes, not version strings, so it flags inconvenient edit ordering and clears with a `touch`, which would also mask a real missed bump. A version-string comparison against the previously-shipped bundle would be more robust.

**They're right.** The v1.11.13 implementation was a shortcut that produced meaningless verdicts:
- Any arm-file edit AFTER the SKILL.md bump would false-fail
- Any `touch skills/<arm>/SKILL.md` would false-pass — including one that hides a real missed bump
- My previous shipping ritual literally called `touch` on arm SKILL.md files to "satisfy the check." That should have been a red flag; instead I shipped it.

**New implementation (v1.11.15+):**

For each arm in the current bundle:
1. Compute a SHA256 of the arm's content (concatenated sorted `*.md` files under `skills/<arm>/`, excluding `SKILL.md` itself)
2. Read the arm SKILL.md's frontmatter `version:`
3. Compare against a `.release-manifest-{edition}.json` shipped with the previous release
4. FAIL only when `content_hash` DIFFERS but `skill_version` is IDENTICAL — the exact condition "arm files changed but SKILL.md wasn't bumped"
5. PASS when content hash matches (nothing changed, no bump needed) OR skill_version differs (bump happened)
6. SKIP for new arms and bootstrap releases

Verified with a live self-test: I injected two lines into `shopify/knowledge/00-overview.md` without bumping the arm SKILL.md and the scanner FAILed with the correct message + content-hash diff. Restored, scanner PASSed. `touch` would not fool this — only a real version bump or unchanged content clears it.

**Note on the previous "PASS" verdicts:** the v1.11.13 and v1.11.14 ship gates reported the mtime scan as PASS. Those verdicts are historically unreliable — they only proved nothing was mtime-newer than SKILL.md, which is trivially achievable with a `touch`. Do not trust them as evidence that no arm-version bumps were missed in v1.11.13 / v1.11.14. The content-hash check starting v1.11.16 (first release with a real manifest baseline) will provide the first trustworthy verdict.
