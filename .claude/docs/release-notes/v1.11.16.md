## TL;DR

Two bugs. Both real. Both mine.

1. **Locale-dependent hash.** The Python writer used codepoint sort; the shell reader used `sort -z` with locale collation. Same untouched tree, `LC_ALL=C` produced `cf453c4f...`, `LC_ALL=en_US.UTF-8` produced `3e3ca339...`. Any UTF-8 environment running the check against a manifest from a C-locale writer would spuriously FAIL every arm on the first real run in v1.11.16. Reproduced the bug locally before fixing.

2. **Manifest not embedded in bundle.** v1.11.15's approach wrote the manifest to `DEST_DIR/.release-manifest-{edition}.json` — external to the bundle. Consequences: (a) master shipping from a clean directory silently SKIPs green (false pass), (b) any window doing standalone verification always SKIPs because the checker's default in-bundle path never existed. The gate depended on directory persistence rather than shipping its own baseline.

Both fixed. No arm content changed in this release — tooling only.

## What changed

### `tools/scripts/verify-edition-integrity.sh`

Content-hash computation now pins `LC_ALL=C` on the `sort -z` step:

```bash
find . -type f -name '*.md' ! -name 'SKILL.md' -print0 2>/dev/null | \
    LC_ALL=C sort -z | xargs -0 cat 2>/dev/null | sha256sum
```

This matches the Python writer's `list.sort()` (codepoint order) regardless of environment locale.

### `tools/scripts/ship-bundle.sh`

Two changes:

1. **Previous-manifest lookup order** — now:
   - Priority 1: `PREV_MANIFEST` env var (explicit override)
   - Priority 2: extract previous release's zip from `DEST_DIR` (auto-find by version-sort of matching slug pattern), read its embedded `.release-manifest.json`
   - Priority 3: legacy `DEST_DIR/.release-manifest-{edition}.json` (backward compat with v1.11.15)
   - Fallback: SKIP with prominent WARNING banner (not a quiet SKIP as before)

2. **New manifest written INSIDE the bundle** at `.release-manifest.json` before rezipping. External `DEST_DIR/.release-manifest-{edition}.json` is still written for backward compat, but the embedded copy is the source of truth. The `SRC_ZIP` passed to ship-bundle.sh gets extracted, manifest embedded, rezipped, then copied to `DEST`.

### End-to-end verification (before shipping)

Reproduced the locale bug on v1.11.15's code and confirmed the fix on v1.11.16:

Confirmed manifest embedding: `unzip -l webdesk-shopify-v1.11.16.zip` shows `.release-manifest.json` inside. Extracted bundle, pointed a fresh verify at the embedded manifest as `PREV_MANIFEST` under UTF-8 — PASS as expected.

## Standalone verification workflow (documented)

Any window can now validate their own build against the last shipped bundle without relying on master's DEST_DIR state:

```bash
# 1. Extract the previous shipped bundle to read its embedded manifest
unzip webdesk-<edition>-v1.11.16.zip -d prev/

# 2. Extract your candidate build
unzip your-candidate-build.zip -d cand/

# 3. Run the checker with PREV_MANIFEST pointing at the extracted manifest
PREV_MANIFEST=prev/webdesk-<edition>-v1.11.16/.release-manifest.json \
  cand/webdesk-<edition>-v1.11.XX/tools/scripts/verify-edition-integrity.sh \
  cand/webdesk-<edition>-v1.11.XX <edition>
```

The check now runs the same way in your environment as it does at master's ship gate.
