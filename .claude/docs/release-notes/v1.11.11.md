## 3 spine escalations addressed

### #17 — HANDOFF next-tasks staleness

**Root cause per HANDOFF:** the queued-task list in `HANDOFF.md` was append-only. Items got done during the session but stayed in the queue. Next session's operator wasted 15+ minutes reconciling.

**Fix (v1.11.11):**
- `_spine/shared-knowledge/handoff-template.md` — added inline RECONCILIATION RULE in the "Next 3 tasks (queued)" section. Rule: at session end, DELETE done items; REWRITE partial items; APPEND genuinely new items. Empty is valid.
- `_spine/shared-knowledge/session-handoff-protocol.md` — new section "Next-tasks staleness — reconciliation at session end (v1.11.11+)" enforcing the rule. Links back to the pilot trigger.

Also flagged: if HANDOFF auto-generation ever exists, it must implement diff-based reconciliation, not append-only.

### #14 — Presentational-only component convention

**Root cause per HANDOFF:** components built pixel-perfect to spec but not wired to their backend (pre-order buttons before the plugin, wishlist before the module) looked "done" in visual QA but produced client confusion at UAT.

**Fix (v1.11.11):**
- `_spine/shared-knowledge/session-handoff-protocol.md` — new section "Presentational-only components — convention (v1.11.11+)". Rule: presentational components render as visually-disabled placeholders with `disabled` + `aria-disabled="true"` + `data-wds-presentational="true"` + `data-wds-activation="{plugin-name}"`. Logged in HANDOFF.
- `_spine/shared-knowledge/handoff-template.md` — new "Presentational-only components" section with format spec: `component-name — activated by {plugin-or-module} — wiring estimate {hours}`.

Applies cross-platform. Not just a WP concern.

### #16 — Canonical design source rule (PNG supersedes HTML mockup per-page with confirmation)

**Root cause per HANDOFF:** on Epoxy Depot a 2×2 grid was implemented per the original HTML mockup; client later provided a PNG showing a big-image layout. Designer + dev didn't know which was canonical for that page. Rebuilt twice.

**Fix (v1.11.11):**
- **New decision code D-DES-03** (details above)
- `_spine/designer-agent/SKILL.md` — new section "Canonical design source per page (D-DES-03, v1.11.11+)". Full rule + per-page register format + anti-patterns.
- Register lives per-project at `outputs/<client_slug>/design-source-register.md` (or inside HANDOFF.md).

**D-DES-01 explicitly unchanged.** HTML mockups remain the WebDesk deliverable. D-DES-03 tracks which INPUT artifact was canonical per page — separate concern.
