## Honest notes

1. **The Elementor architecture file was written FAST.** ~45 minutes for ~280 lines. Some Elementor edge cases (Theme Builder template conditional priority, multi-language ACF + Dynamic Tags interaction, custom widget control types beyond the basics) are covered superficially. Expect to add notes after tomorrow's project surfaces edge cases.

2. **The performance budget targets are baseline.** If tomorrow's client has higher needs (e.g., mobile 85+ target instead of 75+), document that in CLAUDE.md and treat as project-specific.

3. **WC integration patterns are baseline.** Heavy WC customization (custom checkout fields beyond what Elementor's Checkout widget exposes, custom shipping logic) still requires custom code in the underlying theme — Elementor doesn't replace that work.

4. **The Stylelint config is aggressive.** `color-no-hex` and `declaration-no-important` will trip on existing WP / WC code if you point Stylelint at it. Scope Stylelint to YOUR SCSS (`sass/**/*.scss`), not theme overrides or third-party plugin SCSS.

5. **The QA 10-section protocol is comprehensive but slow.** A full pass per page can take 30-45 minutes manually. Use Playwright for the repeatable parts (viewports, console, network, accessibility) — that's where v1.12.0 cross-cutting Playwright skill will help.

6. **D-WP-03 Path A vs Path B decision is now critical at G0.** Choosing wrong means refactoring later. Make the team aware of the rubric.
