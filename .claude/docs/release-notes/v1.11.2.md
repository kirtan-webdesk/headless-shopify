## Why v1.11.2

v1.11.1 shipped with two real gaps:

1. **HANDOFF.md template was missing.** I documented the protocol in `session-handoff-protocol.md` but never produced a copyable template. Team had nothing to put at project root as `HANDOFF.md`.

2. **200K context window error on Claude Code.** v1.11.0/v1.11.1 didn't actually fix the context blowup — the "cascade loader" was instructions to the LLM, not enforced. With 196 files in `skills/`, anything that auto-loads everything blows the limit.

v1.11.2 ships both fixes plus a lean per-project bootstrap workflow.

## What v1.11.2 ships

### 1. `handoff-template.md` (real copyable file)

Location: `skills/_spine/shared-knowledge/handoff-template.md`

Sections: Last session, where we left off, files pushed, files pending push, next 3 tasks, client blockers, open failure modes, decisions made, token usage (optional), what NOT to do on resume, session links, notes for next session. Hard cap: 200 lines.

Copy to project root as `HANDOFF.md` at project start. Update at session end.

### 2. `QUICKSTART-PER-PROJECT.md` (per-project setup guide)

Location: `docs/user-guide/QUICKSTART-PER-PROJECT.md`

The 30-second per-project setup workflow. Tells the team:
- Pick ONE platform per project. Delete the rest from `.claude/skills/`.
- Copy `CLAUDE.md` template + `HANDOFF.md` template to project root.
- Fill in `Required skill files for this project` section in `CLAUDE.md`.
- Start session. Claude reads only what `CLAUDE.md` lists.

Includes common mistakes + recovery when 200K error hits.

### 3. `init-project.sh` (one-command bootstrap)

Location: `tools/scripts/init-project.sh`

Usage:
```bash
tools/scripts/init-project.sh /path/to/new/project --platform wordpress-woocommerce --type new-build
```

Or interactively (prompts for platform, project type, client slug, etc.).

Creates:
- `CLAUDE.md` at project root with placeholders filled
- `HANDOFF.md` at project root (blank, ready for first session)
- Pre-populated `Required skill files for this project` section in CLAUDE.md, scoped to the chosen platform

Validates that `internal_pm_email` ends with `@webdesksolution.ca` (FLAG-004 enforcement).

### 4. Tier 0 audit + cleanup

Demoted from tier 0 → tier 3 (don't auto-load on session start):
- `claude-md-template.md` — it's a template, not a runtime skill
- `frontmatter-spec.md` — it's a schema doc for the validator, not for runtime

Remaining tier 0 files (proper):
- `_spine/persona.md`
- `_spine/orchestrator/SKILL.md`
- `_spine/orchestrator/knowledge/06-agent-cascade.md`

Tier 0 footprint: ~43 KB (down from ~50 KB). Not the main fix — but consistent with the principle.

### 5. Minimal startup instruction in `persona.md`

Top of file, new section: "CRITICAL — Minimal startup load order (v1.11.2)."

Tells the LLM explicitly:
- Read `CLAUDE.md` + `HANDOFF.md` + listed files only
- Do NOT scan the `skills/` tree
- Do NOT auto-load knowledge files
- If `CLAUDE.md` is missing or has no `Required skill files` section, HALT and tell the user

This is the single most important behavioral change in v1.11.2.

### 6. Two release artifacts

**Full release:** `webdesk-ai-delivery-system-v1.11.2.zip` — all platforms (shopify + wordpress-woocommerce + bigcommerce + magento-adobe-commerce). Use this for setup, training, or multi-platform teams.

**Lean WP+Elementor:** `webdesk-wp-elementor-v1.11.2.zip` — spine + wordpress-woocommerce only. 101 files, ~700 KB. Use this for single-WordPress projects (most projects).

## Honest notes

1. **The 200K context fix is behavioral, not architectural.** The persona.md instruction tells the LLM to be disciplined about loading. If the LLM ignores the instruction and reads everything anyway, the problem persists. Watch the next few sessions for compliance.

2. **The lean WP-Elementor bundle is what you should use most of the time.** The full release is for setup / training / multi-platform teams. Single-platform projects = lean bundle.

3. **`init-project.sh` requires bash.** Works on Mac + Linux. On Windows, use Git Bash or WSL.

4. **No content changes from v1.11.1.** All KB files unchanged. v1.11.2 is purely operational fixes.

5. **The 175 file count for the lean bundle includes tools/ and docs/**. Skill markdown files: ~80. Lighter context footprint.

6. **If the LLM still hits 200K context after v1.11.2 setup,** check:
   - Did `CLAUDE.md` get loaded at session start? (Should be visible in conversation history)
   - Did `Required skill files for this project` section list 10-15 files max?
   - Are there extra platform folders in `.claude/skills/`?
   - Run `/compact` to free up history
   - Worst case: end session, update HANDOFF.md, restart
